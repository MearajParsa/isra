# ۰۸ — تحویل طراحی (`design/`)

## اصل طلایی

**AI هیچ اسکرینی را از خود اختراع نمی‌کند.** UI فقط از دارایی‌های داخل `design/` یا brief صریح مالک ساخته می‌شود. اگر دارایی نیست: پیاده‌سازی UI آن صفحه را متوقف کن و در گزارش بگو چه فایلی کم است.

## موجودی UI — کشف on-demand (نه کاتالوگ ازپیش‌پر در docs)

docs-v2 **فهرست پر اسکرین ندارد**. قبل از درخواست design یا کدنویسی UI:

1. AI پیاده‌ساز طبق [`10-ui-discovery-rules.md`](./10-ui-discovery-rules.md) موجودی کامل scope را تولید می‌کند.
2. مالک از روی آن موجودی دارایی را در `design/` می‌گذارد.
3. AI فقط با `screen_id`/`component_id` موجود در موجودی **و** فایل design متناظر کد می‌نویسد.

پوشهٔ `10-ui-inventory/` یا کاتالوگ پر در docs ساخته/نگهداری نمی‌شود.

## محل دارایی

```
Isra/
└── design/
    ├── README.md                 # فهرست اسکرین‌هایی که مالک آماده کرده
    ├── fonts/                    # YekanBakh (قفل فونت)
    ├── low/                      # اسکرین/کامپوننت سطح کاربر
    ├── mid/                      # عملیات جلسه
    ├── high/                     # ادمین
    ├── components/               # دکمه، ورودی، کارت، ...
    └── tokens/                   # اختیاری؛ در غیر این صورت THEME_TOKENS.md
```

ساختار زیرپوشه می‌تواند با مالک تنظیم شود؛ نام فایل‌ها پایدار و انگلیسی باشد.

## قرارداد نام‌گذاری فایل

| الگو | مثال | معنی |
|------|------|------|
| `{level}_{screen}.png` | `low_home.png` | اسکرین کامل |
| `{level}_{screen}_{state}.png` | `mid_queue_empty.png` | حالت |
| `comp_{name}.png` | `comp_primary_button.png` | کامپوننت |
| `{level}_{screen}.md` | `low_home.md` | توضیح/annotation مالک |

سطوح: `low` | `mid` | `high` | `shared`. ترجیحاً نام فایل با `screen_id` موجودی یکی باشد.

## جریان کار AI با design

1. موجودی scope را طبق `10-ui-discovery-rules.md` بساز و خودممیزی کن (اگر هنوز نیست).
2. قبل از ساخت UI، `design/` را برای همان `screen_id` جستجو کن.
3. اگر اسکرین هست: پیکسل/فاصله/سلسله‌مراتب را از تصویر و توکن‌ها پیاده کن؛ فونت **YekanBakh**.
4. رنگ و تایپ را از `THEME_TOKENS.md` بگیر؛ از روی حس اسکرین رنگ جدید نساز مگر مالک گفته باشد.
5. اگر فقط partial هست: همان بخش را بساز؛ بقیه را placeholder ممنوعِ تزئینی — صریحاً «منتظر design» علامت بزن یا نساز.
6. اگر هیچی نیست: **نساز**؛ به مالک بگو کدام `screen_id` از موجودی هنوز design ندارد.
