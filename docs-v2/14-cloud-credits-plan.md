# ۱۴ — برنامهٔ استفاده از Cloud session credits (فرانت در cloud، بقیه محلی)

این سند **قفل محصول نیست**؛ برنامهٔ اجرایی مالک برای تقسیم مصرف توکن است. در تعارض، `00-locks` مقدم است.

## تصمیم مالک
| بخش | کجا اجرا شود | با چه اعتباری |
|-----|--------------|---------------|
| `apps/web-main` (سایت: low + mid) و `apps/web-admin` (پنل ادمین) | **Cloud session** | اعتبار هدیه (Cloud session credits) |
| `services/api-low|mid|high` و `apps/android-low|mid|high` | جلسهٔ محلی (desktop) | سهمیهٔ عادی پلن |
| bootstrap، پیش‌نویس/قفل API، موجودی UI، STATUS | جلسهٔ محلی | سهمیهٔ عادی (کم‌حجم) |

## واقعیت‌های اعتبار (طبق گزارش منابع غیررسمی — در صفحهٔ حساب خود تأیید کن)
- فقط برای اجرای **cloud sessionها** خرج می‌شود؛ روی جلسهٔ محلی اثر ندارد.
- انقضا: **۵ نوامبر ۲۰۲۶ (۱۴ آبان ۱۴۰۵)**. بعد از آن یا اگر تمام شود، cloud هم از سهمیهٔ عادی پلن کم می‌کند.
- پس فرانت باید **زودتر از ۱۴ آبان** در cloud انجام شود؛ اعتباری که نرسد مصرف شود می‌سوزد.

## چرا فرانت بلافاصله قابل شروع نیست (پیش‌نیازها)
طبق `08` و `10`، UI بدون این‌ها ممنوع است. Cloud هیچ‌کدام را نمی‌تواند جای مالک/AI محلی بسازد:

| # | پیش‌نیاز | کجا | مسئول |
|---|----------|-----|-------|
| P1 | اسکلت مونوریپو (`12-bootstrap`) | محلی | AI + تأیید مالک |
| P2 | ریپوی **GitHub** (private) + push | محلی | مالک (ساخت ریپو) |
| P3 | قرارداد API قفل‌شده برای اسکرین‌های وب (auth + low + mid + high) | محلی | AI پیش‌نویس، مالک قفل |
| P4 | موجودی UI web-main و web-admin طبق `10` | محلی یا cloud | AI |
| P5 | دارایی‌های `design/` (اسکرین، فونت YekanBakh) **commit‌شده در ریپو** | محلی | مالک |

Cloud به `D:\` دسترسی ندارد؛ هر چه لازم است باید در ریپو باشد. بک‌اند هنوز نیست، پس فرانت در cloud روی **mock** (بر پایهٔ قرارداد قفل‌شده P3) ساخته می‌شود و اتصال واقعی بعداً محلی انجام می‌شود.

## گام‌ها به ترتیب

### مرحلهٔ A — محلی (مالک + AI، توکن کم)
1. به AI بگو: «شروع پروژه» → طرح bootstrap → تأیید → اسکلت. (P1)
2. مالک: ریپوی private در GitHub بساز، `git remote add origin <url>` و `git push -u origin main`. (P2) — دستور `gh` روی این سیستم نصب نیست؛ از سایت GitHub یا `git` استفاده کن.
3. اپلیکیشن/اتصال GitHub برای Claude را روی همان ریپو فعال کن (تنظیمات cloud در claude.ai/code یا برنامه).
4. «برو سراغ کارstream API» → فقط پیش‌نویس قرارداد endpoint/DTO برای **auth و اسکرین‌های وب** (نه پیاده‌سازی بک‌اند) → قفل مالک. (P3) ماژول `packages/api-types` (DTOهای TypeScript) جای مناسب خروجی است.
5. «برای web-main و web-admin موجودی کامل UI را طبق 10 تولید کن» (P4) → مالک در `design/` طراحی می‌گذارد و commit/push می‌کند. (P5)

### مرحلهٔ B — Cloud (با اعتبار هدیه)
برای هر جلسهٔ cloud: یک برش کوچک، یک branch، یک PR. مثال‌های عبارت:

```
docs-v2/README، 00-locks، 01-product، STATUS را بخوان (کل docs را نخوان).
سپس فقط 04، 08، 10، THEME_TOKENS و design/ را برای اسکرین‌های [گروه X] از web-main بخوان.
با mock API بر پایهٔ packages/api-types بساز. RTL، YekanBakh، توکن‌های THEME_TOKENS.
اسکرینی که design ندارد را نساز؛ فهرستش را گزارش کن.
روی branch feat/web-main-<گروه> کار کن، تست/lint بگذران، STATUS را به‌روز کن و PR بزن.
```

برش‌های پیشنهادی (هر کدام یک جلسه):
1. `web-main`: پایه (layout RTL، تم، فونت، PWA، کامپوننت‌های `design/components`)
2. `web-main`: auth (OTP، رمز، دستگاه‌ها، step-up) روی mock
3. `web-main`: بخش low (خانه، جلسات، پروفایل، اینباکس، امتیاز)
4. `web-main`: بخش mid (جلسه زنده، حضور، صف، ارزیابی — Socket.IO با mock)
5. `web-admin`: پایه + auth
6. `web-admin`: نقش/مجوز، تنظیمات، audit

### مرحلهٔ C — محلی (سهمیهٔ عادی)
بک‌اند و Androidها؛ سپس PRهای cloud را review/merge کن (تصمیم merge با مالک — `OWNER_PLAYBOOK` §۵) و mock را با API واقعی جایگزین کن.

## قواعد جلوگیری از هدر رفتن اعتبار
- هر جلسه یک هدف؛ بعد از تمام شدن PR جلسهٔ جدید.
- `web-main` و `web-admin` را هم‌زمان در دو جلسهٔ جدا بساز (پوشه‌هایشان جداست، تداخل کم).
- قبل از هر جلسه مطمئن شو design همان گروه push شده؛ وگرنه جلسه خالی/گمراه می‌شود.
- جلسهٔ cloud فقط داخل `apps/web-main`, `apps/web-admin`, `packages/api-types` (خواندنی/در صورت لزوم mock) تغییر دهد؛ به `services/` و `apps/android-*` دست نزند.
- خروجی هر جلسه: PR + به‌روزرسانی `STATUS.md` + فهرست اسکرین‌های «منتظر design».
- کمبود مشخصات را حدس نزند؛ پیش‌نویس بدهد (`09`).
