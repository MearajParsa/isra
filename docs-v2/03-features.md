# ۰۳ — ویژگی‌ها بر اساس دامنه

هم‌راستا با قفل‌ها. برای جزئیات مالکیت سرویس → `06-domains/`. برای کشف اسکرین UI → `10-ui-discovery-rules.md` (کاتالوگ ازپیش‌پر در docs نیست).

## ۱) هویت و حساب (`api-low`)

| ویژگی | توضیح |
|-------|-------|
| ثبت‌نام / ورود موبایل ایرانی | شماره `09xxxxxxxxxx`؛ OTP از **Faraz SMS**؛ ۵ رقم / ۲ دقیقه / ۳ تلاش |
| ورود با رمز | پس از تنظیم رمز توسط کاربر |
| بازنشانی رمز با OTP | |
| پروفایل | نام نمایشی، تصویر، تنظیمات پایه |
| مدیریت دستگاه/نشست | لیست نشست‌ها، revoke، revoke خانواده؛ Access ۱۵م / Refresh ۱۴روز rotating |
| Guest browsing | بدون توکن؛ همان محتوای قابل‌مرور عضو؛ اقدام gated → ثبت‌نام/ورود (اصل رشد؛ جزئیات بعداً) |

**ساخته نمی‌شود:** ایمیل، OAuth شخص‌ثالث (مگر unlock)، نقش `guest` در DB.

## ۲) جلسات (`api-mid`)

| ویژگی | توضیح |
|-------|-------|
| ایجاد/ویرایش جلسه | توسط `session_manager` |
| زمان‌بندی انعطاف‌پذیر | یک‌باره، تکرارشونده، بازهٔ محدود؛ هفته شنبه–جمعه، `Asia/Tehran` |
| چرخه حیات | `draft` → `scheduled` → `started` → `ended` — بدون برگشت به عقب |
| مکان | آدرس + نقشه از طریق سرور mid (Map.ir proxy) |
| عضویت | درخواست، تأیید/رد |
| نقش داخل جلسه | manager / supporter / teacher / quran_student |

## ۳) حضور (`api-mid`)

| ویژگی | توضیح |
|-------|-------|
| ثبت ورود به جلسه | یک‌بار امتیاز حضور |
| امتیاز حضور | `+5` فقط یک‌بار per session entry |
| لیست حاضرین زنده | **Socket.IO** روی api-mid وقتی اپ باز است |
| گزارش حضور | برای نقش‌های مجاز |

## ۴) صف نوبت (`api-mid`)

| ویژگی | توضیح |
|-------|-------|
| پیوستن به صف | قرآن‌آموز |
| مدیریت صف | **`session_manager` + `session_supporter` + `teacher`** |
| نوبت فعلی / بعدی | realtime با Socket.IO |
| رد/جابه‌جایی/حذف از صف | مطابق مجوز |

## ۵) ارزیابی (`api-mid`)

| ویژگی | توضیح |
|-------|-------|
| معیارها | صوت، لحن، تجوید |
| وزن | قابل پیکربندی از **high**؛ پیش‌فرض ۴۰ / ۳۰ / ۳۰ |
| ثبت ارزیابی | **فقط** `teacher` و `session_supporter` — `session_manager` به‌تنهایی خیر |
| مشاهده نتیجه | برای قرآن‌آموز و نقش‌های مجاز |
| تأثیر روی امتیاز | طبق قواعد mid |

## ۶) امتیاز و نشان (`api-mid` مالک داده؛ UI در low)

| ویژگی | مقدار |
|-------|-------|
| حضور | `+5` یک‌بار per session |
| نشان‌ها (threshold) | ۵۰ / ۱۵۰ / ۳۰۰ / ۵۰۰ |
| جدول | `badge_awards`؛ با افت امتیاز **باطل نمی‌شوند** |
| نمایش UI | سطح **low**؛ داده از mid با **internal REST** به low (کلاینت low به api-mid مستقیم نزند) |

نام کلید نشان‌ها در کد انگلیسی می‌ماند (مثلاً `badge_50`); برچسب UI فارسی.

## ۷) اینباکس (`api-low` مالک اصلی؛ رویداد از mid/high via outbox/inbox)

| ویژگی | توضیح |
|-------|-------|
| اعلان درون‌برنامه‌ای | عضویت، نوبت، ارزیابی، سیستم |
| خوانده/نخوانده | |
| Poll | وقتی نیاز؛ بدون third-party push |

**ساخته نمی‌شود:** FCM/APNs شخص‌ثالث به‌عنوان کانال اصلی (قفل).

## ۸) قرآن در اپ (کلاینت)

| ویژگی | توضیح |
|-------|-------|
| متن مصحف | PDF محلی در کلاینت |
| صوت | فاز بعد با دانلود؛ **فاز ۱ بدون صوت** |
| ارجاع سوره/آیه برای تکلیف | متادیتا روی سرور مجاز؛ متن آیه نه |

## ۹) ادمین سیستم (`api-high` + `web-admin` / `android-high`)

| ویژگی | توضیح |
|-------|-------|
| مدیریت نقش‌های سیستم | `developer`, `super_admin` undeletable |
| مجوزها (permissions) | مدل کلید انگلیسی |
| تنظیمات سراسری | وزن ارزیابی، آستانه نشان، feature flags داخلی |
| audit / مشاهده کاربران سطح سیستم | مطابق مجوز |
| انتشار تغییر نقش/تنظیمات | internal REST + outbox/inbox به low/mid |

## ۱۰) نقشه

| ویژگی | توضیح |
|-------|-------|
| Map.ir | کلید فقط سرور |
| low | proxy نقشهٔ کاربر |
| mid | proxy مکان جلسه |

## ۱۱) رسانه

| ویژگی | توضیح |
|-------|-------|
| ذخیره فایل | پوشهٔ `media/` روی همان host سرویس |
| MinIO / object-storage جدا | ساخته نمی‌شود (مگر unlock) |

## ماتریس سطح × قابلیت (خلاصه)

| دامنه | low | mid | high |
|-------|:---:|:---:|:----:|
| حساب/OTP/توکن | مالک | auth-only به low | auth-only به low |
| پروفایل/اینباکس | ✓ | — | — |
| امتیاز UI | نمایش (aggregate) | مالک داده | آستانه قابل تنظیم |
| جلسه/حضور/صف/ارزیابی | مشاهدهٔ مجاز از API خود | مالک | نظارت سیستم |
| نقش سیستم/مجوز | دریافت claim | دریافت claim | مالک |
| تنظیمات سراسری | خواندن لازم | خواندن لازم | مالک |
| Socket.IO | — | ✓ | — |
