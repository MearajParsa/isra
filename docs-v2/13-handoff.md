# ۱۳ — تداوم چند-AI و تحویل جلسه (Handoff)

مالک می‌تواند **هر زمان** عامل AI را عوض کند (ابزار، مدل، یا session جدید). هیچ AI حق ندارد فرض کند chat قبلی هنوز در دسترس است. تداوم کار فقط از روی فایل‌های پایدار است.

## منبع حقیقت تداوم

| منبع | نقش |
|------|-----|
| `docs-v2/` | قفل‌ها، محصول، معماری، قواعد کار |
| ریپو / مونوریپو | کد، اسکلت، design، media |
| **STATUS / handoff** | وضعیت زندهٔ کارstream — چه شده، چه مانده |

فایل وضعیت (یکی از این‌ها؛ اولویت با آنچه مالک مشخص کرده):

1. `docs-v2/STATUS.md`
2. `STATUS.md` در ریشهٔ مونوریپو (`D:\project\mobile\cursor\Isra\STATUS.md`)
3. یادداشت `/workspace` هم‌ارز در باکس عامل (اگر مالک مسیر دیگری گفته)

اگر هیچ‌کدام نبود: AI در اولین نیاز **ایجاد** می‌کند (معمولاً `docs-v2/STATUS.md`) و مسیر را در گزارش می‌نویسد.

```
قفل 00-locks > بقیه docs-v2 > STATUS.md > کد موجود > فرض AI / حافظهٔ chat
```

**هرگز** به حافظهٔ گفتگو بین ابزارها یا sessionهای مختلف تکیه نکن.

## تعویض AI توسط مالک

- مالک آزاد است mid-stream ابزار را عوض کند (مثلاً وسط کارstream API، یا برای اصلاح کار قبلی).
- AI جدید **باید** از فایل‌ها شروع کند، نه از «یادم هست که…».
- اگر STATUS قدیمی یا ناقص است: از روی ریپو + docs دوباره بساز، اختلاف را گزارش کن، و STATUS را به‌روز کن — حدس از chat نزن.

## پاس اول AI جدید (اجباری)

ترتیب ثابت — قبل از هر کار عمیق:

1. [`README.md`](./README.md) — نقشه
2. [`00-locks.md`](./00-locks.md) — قفل‌ها

## به‌روزرسانی اجباری STATUS.md

AI **باید** `STATUS.md` را به‌روز کند وقتی:

- مالک می‌گوید session را ببند / handoff / تحویل بده
- قبل از پایان طبیعی جلسهٔ کاری
- پس از اتمام یک task معنادار یا قفل شدن مشخصات جدید
- وقتی AI عوض می‌شود و STATUS ناقص است (اول پر کن، بعد ادامه بده)

### قالب حداقلی STATUS.md

```markdown
# STATUS — اسراء (Isra)

آخرین به‌روزرسانی: <تاریخ Asia/Tehran> — توسط: <نام/ابزار AI>

## انجام‌شده (Done)
- …

## در حال انجام (In progress)
- کارstream: …
- آخرین گام کامل‌شده: …
- شاخه/مسیر کد: …

## بعدی (Next)
1. …
2. …

## قفل‌های تازه / پیش‌نویس در انتظار تأیید
- …

## سؤالات باز
- …

## مسیرهای کلیدی
| مورد | مسیر |
|------|------|
| docs-v2 | … |
| STATUS | … |
| ماژول/فایل فعال | … |
| پیش‌نویس API/schema | … |
```

بخش‌های خالی را حذف نکن — با `—` یا «هیچ» علامت بزن تا AI بعدی بداند بررسی شده.

## ادامه mid-stream (مثال‌ها)

| موقعیت | رفتار AI جدید |
|--------|----------------|
| وسط کارstream API | STATUS → پیش‌نویس endpoint/schema اشاره‌شده → فقط فایل‌های ردیف API در `11` → از آخرین task تأییدشده ادامه؛ اختراع دوباره نکن |
| اصلاح کار قبلی | STATUS + diff/فایل‌های نامبرده در Done/In progress → با قفل‌ها بسنج → فیکس محدود؛ بازنویسی کل مگر مالک بخواهد |
| بعد از bootstrap ناتمام | STATUS + چک‌لیست [`12-bootstrap.md`](./12-bootstrap.md) → فقط کمبود اسکلت؛ feature نزن |
| کلاینت/UI نیمه‌کاره | STATUS + موجودی UI اشاره‌شده + `10`/`08` در حد نیاز → بدون invent اسکرین |
| سؤال کوتاه مالک | پاس اول (README→00→01→STATUS)؛ اگر STATUS جواب می‌دهد deep-read نکن |

همیشه: طرح کوتاه «از کجا ادامه می‌دهم» بده اگر ابهام داری؛ بعد از تأیید پیش برو.

## ممنوع

| ممنوع | |
|-------|--|
| تکیه به chat memory بین ابزارها / sessionها | |
| ادامهٔ کار بدون خواندن STATUS وقتی فایل وجود دارد | |
| بستن جلسه بدون به‌روزرسانی STATUS (مگر مالک صریحاً بگوید لازم نیست) | |
