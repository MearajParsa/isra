# راهنمای مالک پروژه (Mearaj) — OWNER_PLAYBOOK

این فایل فقط برای **شما به‌عنوان مدیر انسانی پروژه** است؛ نه برای جزئیات کدنویسی AI.  
نقش شما: مدیریت، تأیید، قفل تصمیم‌ها، و دادن اسکرین‌شات/طراحی. کدنویسی را AI انجام می‌دهد.

---

## ۱) docs-v2 چیست و شما چه کار می‌کنید؟

| مورد | توضیح |
|------|--------|
| **docs-v2** | بستهٔ مستندات رسمی پروژه اسراء؛ منبع حقیقت برای هر AI کدنویس |
| **شما** | فقط **مدیریت** می‌کنید: دستور کارstream، تأیید طرح، قفل تصمیم، طراحی در `design/` |
| **AI** | بعد از تأیید شما اسکلت/کد می‌نویسد؛ از docs-v2 تدریجی می‌خواند |

شما لازم نیست فایل‌های فنی را خط‌به‌خط بخوانید. کافی است این playbook + `STATUS.md` را دنبال کنید. جزئیات اجرا داخل:

- [`12-bootstrap.md`](./12-bootstrap.md) — شروع اسکلت
- [`11-context-and-reading.md`](./11-context-and-reading.md) — چه چیزی را AI بخواند
- [`13-handoff.md`](./13-handoff.md) — تعویض AI / ادامه کار
- [`10-ui-discovery-rules.md`](./10-ui-discovery-rules.md) — موجودی UI برای طراحی

---

## ۲) اولین بار: گذاشتن docs-v2 در پروژهٔ جدید

1. کل پوشهٔ `docs-v2` را در مسیر پروژه کپی کنید (معمولاً ریشهٔ مونوریپو):
   - هدف شناخته‌شده: `D:\project\mobile\cursor\Isra\docs-v2`
2. اسناد قدیمی (`new docs/` و مشابه) را **دست نزنید** و به AI نگویید عوضشان کند.
3. به AI بگویید فقط این‌ها را بخواند (نه همهٔ فایل‌ها):

```
لطفاً README و فایل‌های 11 و 12 و 13 در docs-v2 را بخوان، بعد منتظر دستور من بمان.
```

یا کوتاه‌تر:

```
docs-v2 را طبق OWNER_PLAYBOOK شروع کن: اول README + 11 + 12 + 13 را بخوان؛ کل پوشه را dump نکن.
```

پس از آن AI باید پاس اول استاندارد (README → `00-locks` → `01-product` → `STATUS`) را هم رعایت کند؛ شما فقط مسیر درست را نشان می‌دهید.

## ۳) عبارات دقیق برای گفتن به AI

از همین جمله‌ها (یا خیلی نزدیک) استفاده کنید تا کارstream درست فعال شود.

### شروع پروژه / بوت‌استرپ اسکلت

```
پروژه را شروع کن / bootstrap / اسکلت مونوریپو را بساز.
طبق 12-bootstrap طرح بده، تأیید بگیر، بعد اسکلت خالی بساز — بدون feature و بدون Docker.
```

### کار API / بک‌اند

```
برو سراغ کارstream API.
طبق 11 پیش‌نویس endpoint و schema بده؛ قبل از کد، تأیید من را بگیر.
```

### کلاینت android-low (یا mid / high)

```
شروع android-low.
اول طبق 10 موجودی کامل UI بساز؛ کد UI نزن تا من در design/ طراحی کنم و تأیید بدهم.
```

(به‌جای `android-low` می‌توانید بگویید: `android-mid`، `android-high`، `web-main`، `web-admin`، یا «سطح low / mid / high».)

### تعویض AI / ادامه با AI جدید

```
AI عوض شد. STATUS.md را بخوان و از همان نقطه ادامه بده.
به حافظهٔ chat قبلی تکیه نکن. طبق 13-handoff عمل کن.
```

### تولید موجودی UI برای طراحی

```
برای [android-low / سطح low / …] موجودی کامل UI را طبق 10-ui-discovery-rules تولید کن
تا من در design/ طراحی کنم. هنوز کد UI ننویس.
```

### به‌روزرسانی STATUS

```
STATUS.md را به‌روز کن: Done / In progress / Next را با وضعیت فعلی پر کن.
```

قبل از بستن جلسه یا تعویض ابزار، همین را بگویید (یا بگویید «handoff / تحویل بده»).

---

## ۴) تحویل چند-AI (Handoff)

وقتی ابزار/مدل/session عوض می‌شود:

1. فایل [`STATUS.md`](./STATUS.md) را باز کنید و ببینید Done / In progress / Next چیست.
2. به AI جدید **پیست** کنید (نمونه):

```
docs-v2 را داری. STATUS.md را بخوان.
کارstream فعال و Next را از STATUS بگیر و ادامه بده.
قفل‌ها در 00-locks مقدم‌اند. به chat قبلی تکیه نکن.
جزئیات: 13-handoff و 11-context-and-reading.
```

3. اگر STATUS خالی/کهنه است، بگویید از روی ریپو + docs دوباره بسازد و اختلاف را گزارش کند — حدس نزند.

جزئیات کامل: [`13-handoff.md`](./13-handoff.md).

## ۵) نقاط تأیید شما (Approval)

بدون تأیید صریح شما، AI نباید از این‌ها عبور کند:

| نقطه | شما چه می‌کنید؟ |
|------|------------------|
| **قفل‌ها (`00-locks`)** | تصمیم جدید یا تغییر قفل فقط با تأیید شما؛ AI حق باز کردن قفل ندارد |
| **پیش‌نویس endpoint / schema** | قبل از پیاده‌سازی API، پیش‌نویس را بخوانید و قفل کنید |
| **موجودی UI** | جدول اسکرین/کامپوننت را بررسی کنید؛ بعد در `design/` طراحی کنید |
| **طرح bootstrap / اسکلت** | قبل از ساخت پوشه‌های ریشه، طرح را تأیید یا اصلاح کنید |
| **تصمیم merge / ادغام شاخه** | شما تصمیم نهایی merge را می‌گیرید؛ AI فقط پیشنهاد/آماده‌سازی می‌دهد مگر صریحاً بگویید merge کند |

قانون کلی: **طرح → تأیید شما → اجرا**. اگر شک دارید بگویید: «فقط طرح بده، کد نزن.»

---

## ۶) چه کارهایی را خودتان نکنید

| نکنید | چرا |
|-------|-----|
| خودتان کد ننویسید / اسکلت دستی نسازید | نقش شما مدیریت است؛ بوت‌استرپ و کد کار AI است (`12`) |
| نگویید «همهٔ فایل‌های docs-v2 را بخوان» | توکن و تمرکز خراب می‌شود؛ خواندن تدریجی اجباری است (`11`) |
| قفل‌ها را بدون ثبت در `00-locks` عوض نکنید | منبع حقیقت باید پایدار بماند |
| اسناد قدیمی (`new docs/`) را مبنای کار نکنید | در تعارض، docs-v2 و قفل‌ها مقدم‌اند |
| بدون موجودی UI و بدون دارایی `design/` از AI UI نخواهید | اختراع اسکرین ممنوع است (`10` / `08`) |
| به حافظهٔ chat بین ابزارها تکیه نکنید | فقط `STATUS.md` + docs + کد |

## ۷) ترتیب معمول کار

```
۱) کپی docs-v2 در مسیر پروژه
۲) به AI: README + 11 + 12 + 13
۳) Bootstrap (اسکلت خالی مونوریپو) — تأیید شما
۴) کارstream API (پیش‌نویس endpoint/schema → قفل → کد)
۵) موجودی UI (طبق 10) → شما طراحی در design/
۶) کلاینت‌ها (android-low/mid/high، web-main، web-admin) با دارایی design
```

Auth معمولاً زیرمجموعهٔ کار API است. دامنه‌های mid / low / high را می‌توانید جدا سفارش دهید. هر جا AI عوض شد → `STATUS` + عبارت handoff بخش ۴.
